# 等级 1：直连 API——先跟模型"裸聊"

> 预计耗时：1–2 周
> 核心认知：**LLM API 是无状态的，每一轮对话都是你把历史拼起来重新发给它。** 这个认知没建立，后面全是空中楼阁。

## 目标

不借助任何框架，纯代码调通 LLM API，理解它的无状态本质。

## 需要掌握

- 基本概念：token、上下文窗口、温度参数、system/user/assistant 三种消息角色
- 不用任何框架，直接用 OpenAI 兼容 SDK 调用（智谱 GLM、DeepSeek、Qwen 都兼容 OpenAI 接口格式）
- 自己维护 `messages` 列表实现多轮对话
- 流式输出（streaming）
- 结构化输出：让模型稳定输出 JSON 并做解析兜底
- 基础工程习惯：超时重试、限流处理、记录每次调用的 token 花费

## 避坑

- 一上来就学 LangChain 之类的框架，底层 API 不懂，出问题完全不会排查
- 以为模型"记得"上一轮说的话——其实是你没把历史传过去
- Prompt 写得含糊，效果差就怪模型笨，而不是回去改指令
- 不处理超时和限流，程序偶发崩溃还找不到原因
- 调试时反复全量重跑，token 费用失控

## 练习清单

- [ ] 命令行多轮聊天机器人：自己维护对话历史，支持退出时保存
- [ ] 评论分类器：输入商品评论，输出 `{"情感": "...", "类别": "...", "置信度": ...}`，处理 JSON 解析失败
- [ ] 本地文档摘要工具：读 txt/md 文件，输出三句话摘要

## 晋级标准（全部打勾后进入等级 2）

- [ ] 不查资料能写出完整多轮对话程序，正确维护 messages 列表
- [ ] JSON 输出有解析失败的兜底逻辑（重试或修复）
- [ ] 能向别人讲清楚"API 无状态、上下文是拼出来的"
