range(1, 4)

  2. 进入循环 2

Retrieval · 3 min

先把昨天的循环从记忆里叫出来

先不要打开旧代码。请在纸上、记事本或聊天框里补完下面两处；费力回忆比重读更能加固记忆。

guess = 0

while ____________:
    guess = int(input("请猜："))
核对停止条件 
while guess != 7:
    guess = int(input("请猜："))

条件表达的是“还没有猜中”。循环内更新 guess，条件才可能变成 False。

回忆题：如果循环里不更新 guess，会发生什么？

条件会一直使用同一个旧值，程序可能永远无法正常停止。意外进入无限循环时，在终端按 Ctrl + C。

Understand

for：依次取值，每个值做一轮

先读一个只执行三轮的最小例子：

for epoch in range(1, 4):
    print(f"第 {epoch} 轮")

print("全部完成")

1. 给出数字

range(1, 4) 依次提供 1、2、3，不会提供终止值 4。

2. 取出一个

for 每轮把下一个数字赋给 epoch；不需要你手动写 epoch = epoch + 1。

3. 执行一轮

缩进块对每个数字执行一次。数字取完后，程序继续执行循环外的代码。

运行前预测

不要运行，先写下输出顺序。特别留意最后一行出现几次。

for number in range(1, 4):
    print(number)

print("停")
展开预测答案 
1
2
3
停

4 是停止边界，不会进入循环；“停”没有缩进，所以在整个循环结束后只输出一次。

Boundary

range() 的两种入门写法

写法 实际提供的数字 适合的表达
range(3) 0, 1, 2 从零开始，恰好执行 3 次
range(1, 4) 1, 2, 3 显示给人看的第 1、2、3 轮
为什么常写 epochs + 1？ 如果用户输入 epochs = 3，而你想显示第 1 到第 3 轮，就要写 range(1, epochs + 1)。终止值不包含，所以把边界放在目标值的后一个整数。

第三个参数 step 可以改变步长，例如 range(2, 7, 2) 给出 2, 4, 6。今天只需要能看懂，不要求主动使用。

Choose the loop

先问任务，再选 while 或 for

任务 更自然的循环 理由
一直猜，直到猜对 while 开始时不知道会猜几次，停止取决于条件
明确模拟 5 轮训练 for 次数已知，可以依次取出 5 个轮次编号

这不是死规定，而是当前阶段很好用的选择法：次数未知，看条件；次数已知，看序列。

Checkpoint 1 · Build

做一个训练轮次模拟器

在 Python 文件夹中新建 training_rounds.py，亲手输入下面的代码。这里模拟的是控制流，不是真实机器学习训练。

epochs = int(input("准备模拟几轮训练？ "))
score = 60

for epoch in range(1, epochs + 1):
    score = score + 5
    print(f"第 {epoch} 轮：模拟得分 {score}")

print(f"训练结束，最终模拟得分 {score}")

保存后，在 PowerShell 中运行：

cd "C:\Users\ZhongHui\Documents\ChatGPT\学习\Python"
python training_rounds.py
固定测试输入：3 应依次看到第 1、2、3 轮，模拟得分依次为 65、70、75，最后只输出一次“训练结束”。
epoch 为什么不需要提前赋值？

for 每轮都会从 range() 取出一个值并赋给 epoch。第一次是 1，接着是 2 和 3。

score 为什么要在循环之前设为 60？

循环第一轮需要读取旧的 score 再加 5，所以第一次进入循环前它必须已经存在。它会把每轮的更新保留下来。

Checkpoint 2 · Trace

追踪三轮状态

输入 3 时，range(1, epochs + 1) 等价于 range(1, 4)。

循环时刻 epoch 更新前 score 更新后 score
第 1 轮 1 60 65
第 2 轮 2 65 70
第 3 轮 3 70 75

第三轮结束后，range() 已经没有下一个数字；for 自动退出，不需要额外写停止条件。

Checkpoint 3 · Debug

亲手制造一次少一轮

把循环行临时改成下面这样，用输入 3 再运行一次：

for epoch in range(1, epochs):

先预测：会出现哪些轮次？运行后再展开答案。

查看原因与修复

只会出现第 1、2 轮，因为终止值 3 不包含。这类“少一次”常叫边界错误。恢复为：

for epoch in range(1, epochs + 1):
Interleave

把旧 while 翻译成新 for

下面的 while 会输出 1、2、3。试着用两行 for 写出相同行为。

count = 1

while count <= 3:
    print(count)
    count = count + 1
核对 for 版本 
for count in range(1, 4):
    print(count)

两段都正确；当目标只是依次处理固定的三个数字时，for 更直接，也省去了手动更新 count。

Retrieval · Finish

合上代码，用自己的话回答

Q1：range(1, 4) 会依次提供哪些数字？

1、2、3。开始值包含，终止值 4 不包含。

Q2：为什么显示 1 到 epochs 时要写 epochs + 1？

因为 range() 不包含终止值；把终止边界放在目标值后面，最后一个目标值才会被取到。

Q3：for 循环里的 epoch 是谁更新的？

for 自动从 range() 取出下一个值并赋给 epoch，不需要手动加一。

Q4：什么时候更适合 while，什么时候更适合 for？

重复次数未知、依赖条件停止时优先考虑 while；要依次处理一组值或已知次数时优先考虑 for。
