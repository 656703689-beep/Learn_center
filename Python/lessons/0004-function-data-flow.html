Why a function?

先给一段工作起名字

猜数字程序里，“比较 guess 和 secret”是一件边界清楚的工作。把它变成函数后，主程序只需提出请求并接住结果：

result = compare_guess(20, 30)
print(result)

函数负责一件事

compare_guess 只比较两个数字，不读取键盘，也不决定循环多少次。

主程序组织步骤

主程序收集输入、调用函数，再决定在哪里显示返回的结果。

这种“输入数据 → 函数处理 → 返回结果”的形状，会反复出现在后续 AI 程序的数据预处理、模型调用和结果判断中。

Understand

读懂定义、调用与返回

def compare_guess(guess, secret):
    if guess < secret:
        return "太小了"
    elif guess > secret:
        return "太大了"
    else:
        return "猜中了"

message = compare_guess(20, 30)
print(message)
代码 名字 这一刻发生什么
def compare_guess(...): 定义 创建函数并给它命名；这里只定义，不执行函数体
guess, secret 参数 函数内部用来接收数据的名字
compare_guess(20, 30) 调用 把实参 20、30 交给函数并执行函数体
return "太小了" 返回 结束这次调用，把字符串交回调用的位置
参数是名字，实参是这次交进去的值 调用 compare_guess(20, 30) 时，guess 接到 20，secret 接到 30。
Trace before run

先预测这次调用

不要运行，沿着四步数据流回答：

message = compare_guess(40, 30)
print(message)
  1. guess 接到什么值？
  2. secret 接到什么值？
  3. 哪个判断为 True？
  4. message 最终保存什么？
展开数据流答案

guess = 40，secret = 30；第二个判断 guess > secret 为 True，所以函数返回 "太大了"，这个字符串随后被赋给 message。

Checkpoint 2 · Connect

把键盘输入交给函数

前三次固定调用都正确后，把文件底部的三行 print(...) 临时注释掉，再添加：

secret = 30
guess = int(input("猜一个 1 到 30 的整数："))

result = compare_guess(guess, secret)
print(result)

这次主程序负责输入与输出，函数仍然只负责比较。分别输入 10、30、40，验证三条路径。

print 和 return 是一回事吗？

不是。print() 把文字显示在终端；return 把值交回调用处，让主程序还能保存、判断或继续处理它。这里先 return 给 result，再由主程序 print(result)。

Checkpoint 3 · Debug

为什么什么都没有输出？

下面的程序运行后没有报错，也没有显示“太小了”：

def compare_guess(guess, secret):
    if guess < secret:
        return "太小了"

问题不在 if，而在函数只被定义、没有被调用。请凭记忆补两行，让结果显示出来。

核对修复 
result = compare_guess(10, 30)

Retrieval · Finish

合上代码，用自己的话回答

Q1：def 那一行会立刻执行函数体吗？

不会。它创建并命名函数；看到函数调用时，函数体才执行。

Q2：compare_guess(20, 30) 中的 20 和 30 叫什么？

它们是这次调用传入的实参；函数定义中的 guess 和 secret 是参数。

Q3：return "太小了" 做了哪两件事？

结束当前函数调用，并把字符串 "太小了" 交回调用位置。

Q4：为什么不直接在函数里 print？

返回值可以继续保存、判断或组合；显示结果只是主程序可能选择的一种后续操作。
