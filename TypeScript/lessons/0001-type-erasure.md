### §0.3 两行 tsconfig（2 分钟）

在工作区根目录新建 `tsconfig.json`，内容只有这些：

```json
{
  "compilerOptions": {
    "strict": true,
    "noEmit": true
  }
}
```

为什么需要它：**没有这个文件，编辑器对散装的 `.ts` 文件默认不开 strict**——你看到的红线是"宽松版"的，和课程底线"strict 下 0 error"对不上。注意这不是总纲里砍掉的"tsconfig 全家桶"：全家桶指网上抄来的二十行陈年配置（target ES5、各种 paths），这里只有两个开关，每个都说得清——

- `strict`：把严格检查一揽子打开（§2.4 细说），课程的底线；
- `noEmit`：只检查、不产出 JS 文件（我们用 tsx 直跑，不需要 tsc 生成产物）。

## §1 核心认知：类型会被擦除

> ◆ **本课唯一必须带走的东西**
>
> **TypeScript = JavaScript + 编译期类型检查。类型在编译后被完全擦除（type erasure），管不到运行时。**

眼见为实。左列是你写的，右列是抹掉类型后真正跑在 Node 上的 JavaScript：

```typescript
// 你写的 demo.ts                        // 编译产物 demo.js（真正的运行时）
let price: number = 9.9;                 let price = 9.9;
const names: string[] = [];              const names = [];
function fee(n: number): string {        function fee(n) {
  return `￥${n}`;                         return `￥${n}`;
}                                        }
```

四处理类型——`number`、`string[]`、参数的 `n: number`、返回值的 `string`——在产物里一个都不剩。**Node 从头到尾没见过你的类型，它跑的就是右列。**

三个推论，每个都值回今天的学费：

1. **编译器说没问题 ≠ 运行时不会炸。**类型检查是发车前安检，不是全程护送。安检查的是"你写代码的手"，管不了"数据实际长什么样"。
2. **tsx 跑通 ≠ 类型没错。**tsx 为了快，根本不做类型检查（§0.4 那条沉默的 tsc 才是检查）。"能跑"和"类型对"是两件独立的事，两条命令各管一件。
3. **从外面进来的数据没有类型。**用户输入、`JSON.parse`、网络返回——类型只存在于你写的代码里。给这种数据写注解，本质是"你向编译器声称它长这样"：编译器信你，事实未必配合。

> ⚠️ **本课避坑**
> 建立这个认知后别走另一个极端——"类型反正管不到运行时，那有什么用"。它的用处恰恰是把一大类错误从"运行时随机爆炸"提前到"你写代码的这一秒就红线"。前提是别用 `any` 把安检通道整个关掉：any 的意思是"我放弃检查"，一旦写下去，所有依托它的代码都退回裸奔的 JavaScript。

### §1.1 动笔预测（5 分钟）

别只看。下面 4 段代码，**先别用 IDE**，逐段预测：`tsc --noEmit` 报不报错？tsx 跑起来炸不炸？（三种可能：只编译错 / 只运行炸 / 都没事）

```typescript
// A
const price: number = "9.9";

// B
const user: { name: string } = JSON.parse('{"nama": "typo"}');
console.log(user.name.length);

// C
const scores: number[] = [90, 85];
const first: number = scores[9];
console.log(first + 1);

// D
let count: number = 0;
count = count + 1;
```

写完再对照（猜错很正常，错在哪就是哪没懂）：

> [!success]- 对照答案（先写完再展开）
> **A：只编译错。**tsc 会说 `Type 'string' is not assignable to type 'number'`。但用 tsx 跑？**照跑不误**，price 里躺着字符串 `"9.9"`——这一眼就是类型擦除本身：运行时没人拦你。
>
> **B：编译放行，运行炸。**`JSON.parse` 返回 `any`（§4 细说），any 可以赋给任何注解，所以 tsc 沉默；跑起来 `user.name` 是 `undefined`，`.length` 直接 `TypeError`。声称 ≠ 事实。
>
> **C：编译放行，运行不炸——但更糟。**越界下标 `scores[9]` 运行时是 `undefined`，`undefined + 1` 得 `NaN`，程序静默打出 `NaN`。没崩溃的错误最难发现。（这个口子有个专门的开关 `noUncheckedIndexedAccess` 堵，不在 strict 里、要单独开，后面等级再启用，今天知道有这坑就行。）
>
> **D：没事。**正常代码，用来校准你有没有过度怀疑。
>
> 四段合起来就是本课全部：类型挡得住 A，挡不住 B 和 C——**A 是你写错，B/C 是数据不配合。**类型系统防前者，防不了后者；后者的解法叫"边界校验"，是第 4、6 次课的正题。

## §2 看清你写下的东西（30 分钟）

学前阅读讲"每个类型是什么"。这一节讲三件手册不会直说的事：工具怎么分工、注解什么时候写、Python 习惯哪里会坑你。

### §2.1 tsx 与 tsc：一个发车，一个安检

| | `npx tsx 文件.ts` | `npx tsc --noEmit` |
|---|---|---|
| 检查类型？ | ❌ 完全不检查 | ✅ 只干这个 |
| 跑你的代码？ | ✅ | ❌ |
| 出 JS 产物？ | ❌（内存里转译） | ❌（noEmit；去掉它才产出） |
| 什么时候用 | 日常开发，改完就跑 | 练习完成前，验 0 error |

二者没有替代关系。任务 3 你还会见到第三种用法：`npx tsc --strict --outDir tmp 文件名.ts`——真的编译出 JS 文件，用来看"类型擦除后剩下什么"。

### §2.2 注解 vs 推断：谁来写类型

TypeScript 给变量定类型有两套路子：

```typescript
let price: number = 9.9;   // ← 注解（annotation）：你亲手写
let total = 19.8;          // ← 推断（inference）：编译器从初始值推出来，一样是 number
```

推断不是"没有类型"——类型一样存在，只是编译器替你写了。验证方式：编辑器里**悬停**变量名，浮窗里的就是推断结果。写代码时随手悬停，是这门课的基本功。

什么时候写、什么时候省，一条规则够用：

> **函数边界必须写，函数体内能省则省。**

```typescript
function bmi(height: number, weight: number): number {   // ← 参数没有初始值可推，必须写
  const h = height / 100;                                 // ← 体内：初始值摆着，推断得比手写准
  return weight / (h * h);                                // ← 返回值建议写：函数对外的"合同"
}
```

参数不写 = 隐式 any = 安检放行一切（strict 不惯着这个，会直接报错，见 §2.4）。返回值写上，一是当文档，二是防你手滑 return 错东西。两个值得知道的细节：

- `const x = "hello"` 推出**字面量类型** `"hello"`；`let x = "hello"` 推宽为 `string`——const 不会再变，编译器敢推得窄；
- 推断链断了（比如先声明后赋值），悬停看到的就是断点——要么补注解，要么改写法。

### §2.3 今天的弹药库 + Python 对照

| TypeScript | Python | 差异点 |
|---|---|---|
| `string` | `str` | — |
| `number` | `int` / `float` | **没有整数小数之分**，全是浮点：`3 / 2 === 1.5` |
| `boolean` | `bool` | — |
| `null` / `undefined` | `None` | JS 有两个空：undefined = "没赋过值"，null = "故意置空"；第 3 次课的主角 |
| `string[]` / `number[]` | `list[str]` | — |
| `string \| number` | `str \| float`（3.10+） | 联合类型：可以是其中任何一种 |
| `"small" \| "large"` | `Literal["small", "large"]` | 字面量类型：值本身就是类型；今天 BMI 的主角 |

> ⚠️ **从 Python 带来的三个坑**
> 1. **比较永远用 `===`。**`==` 会隐式转换：`"1" == 1` 是 `true`，`0 == ""` 也是 `true`。本课程和绝大多数团队规范把 `==` 视为笔误。
> 2. **`+` 会静默拼接。**Python 里 `"1" + 1` 当场 TypeError；JS/TS 里得到字符串 `"11"`，不报错不警告，直到很远的地方才炸。
> 3. **数字全是浮点。**没有 `//` 整除，`7 / 2` 是 `3.5`；要整除用 `Math.floor(7 / 2)`。算数组下标时尤其小心。

### §2.4 strict 到底开了什么

`strict` 是一揽子开关的简写，最出名的是 `strictNullChecks`：没有它，`null` / `undefined` 可以赋给**任何**类型——空值完全不设防。开了它：

```typescript
let name: string = "小钟";
name = null;   // ← strict: Type 'null' is not assignable to type 'string'
               //   不开 strict：放行，然后某个 name.length 在运行时炸给你看
```

strict 下的满屏红不是找麻烦，是编译器在逐个指出"这里可能没值"。今天只建立这个印象；怎么逐个回应红线，是第 3 次课（窄化）的正题。你今天会实际遇到的另一个成员是 `noImplicitAny`：函数参数不标类型直接报错——这就是"参数必须写注解"的出处。

3. 类型注解什么时候必须写、什么时候该省？你的判断标准是什么？

自测五题（每题先默答，再点开「看答案」）：

**Q1. 一段 TypeScript 从按下运行到打印结果，类型经历了什么？**

> [!question]- 看答案（先默答再点开）
> **被检查一次，然后完全擦除。**
>
> 你写的 `.ts` 先经过类型检查（编辑器实时查，或 tsc 手动查；tsx 只转译不查），然后所有类型信息被剥掉，Node 跑的是纯 JavaScript。运行时没有"类型"这个概念——你注解里写的 `string`、`number` 早就没了。

**Q2. `npx tsx` 跑通了一段代码，能说明类型没错吗？**

> [!question]- 看答案（先默答再点开）
> **不能，tsx 根本不做类型检查。**
>
> "能跑"只说明 JavaScript 语义没炸——类型错误照样能跑（§1.1 的 A）。类型对不对，以 `npx tsc --noEmit` 沉默为准。反过来，tsc 通过也不能保证运行不炸——两边各管一半，缺一不可。

**Q3. `JSON.parse` 的返回类型是什么？它为什么能赋给 `const data: { name: string }` 还不报错？**

> [!question]- 看答案（先默答再点开）
> **`any`。any 能双向赋给任何类型，编译器直接放行。**
>
> JSON 里装的是运行时才知道的数据，编译器不可能知道形状，所以 `JSON.parse` 的签名返回 any——含义是"我放弃检查"。你的注解 `{ name: string }` 只是一份**声称**，编译器采信了；运行时数据不配合，照样炸。真正的解法是运行时校验：第 4 次手写守卫，第 6 次 zod。

**Q4. 类型注解什么时候必须写？什么时候该省？**

> [!question]- 看答案（先默答再点开）
> **函数参数必须写（没有初始值可推，strict 下不写直接报错）；返回值建议写（对外的合同）；有初始值的变量让编译器推。**
>
> 一条标准：**边界写死，内部放手。**边界（函数签名）是别人阅读和调用的依据，必须明确；内部变量的类型悬停可见，推断比手写更不会和现实脱节。

**Q5. 既然类型会被擦除、管不到运行时，TypeScript 图什么？**

> [!question]- 看答案（先默答再点开）
> **它把一大类错误从"运行时随机爆炸"提前到"编写时红线"，并逼你把数据的形状想清楚。**
>
> 你写错的手（把字符串当数字用、把空值当有值用），编译期全拦下——这类错误在纯 JS 里要靠测试甚至线上事故才发现。至于运行时数据不配合（§1.1 的 B、C），类型确实管不到，那部分的答案叫"边界校验"，第 4、6 次课见。
